Written 2026-11-09.

## Start with this

Port `lib/form-schema.ts` to Pydantic in a scratch file, then compare
`model_json_schema()` with the output of `GET /api/schema`.

It takes under an hour, needs no decisions, and answers the real question:
does the schema survive the move to Python cleanly? If the two JSON Schemas
match (thirteen element types, discriminated on `type`), the FastAPI port is
translation work. If they don't, you have found the hard part early.

## Where things stand

- The app works end to end: Next.js 16, AI SDK 7, zod. Pushed to
  `github.com/dalager/chatmodeller`, `main` is clean.
- Tested against the local model in `.env.local`: builds a form from one
  message, edits a selected element with chained tool calls, no tool errors.
- `/architecture` documents the flow; `docs/architecture.png` is a capture of
  its overview diagram.

## The decision that is still open

Stay on Next.js, or move the backend to Python?

What we concluded today:

- The backend is ~700 lines and nothing in it is Next.js-specific.
  `form-ops.ts` is pure functions and ports mechanically.
- Three things the AI SDK does today must be rewritten: the tool loop, parsing
  streamed tool calls, and the event stream to the browser.
- Leaning: plain FastAPI + SSE, own event protocol (text delta, tool started,
  tool result with new form, done), drop `useChat`. Loop via the `openai`
  client or Pydantic AI.
- LangGraph: works, but it wants to own the form as server state, which is the
  opposite of "the browser owns the form". Only worth it for approval steps,
  server-side persistence or several agents.
- The real cost of Python: the schema stops being shared. Pydantic becomes the
  source of truth and the frontend needs generated types.

## Loose ends

- **The endpoint is slow.** 1.5–2+ minutes per turn. A 24-token prompt took
  45 s before the first token on one call and generated at 5.5 tokens/s on
  another. This is the model server, not the app. Look at the machine before
  judging the chat UX.
- **Browser walkthrough on the real model is not done.** The UI was only
  driven end to end against a mock LLM. The real model was tested through the
  API route.
- **Not verified:** whether Pydantic AI's Vercel adapter speaks the AI SDK 7
  stream format. Only matters if `useChat` is kept.
- `OPENAI_REASONING_EFFORT=none` is set in `.env.local`. Fastest, quality held
  in one run. Try `low` once the endpoint is healthy.
- Chat history is lost on reload; only the form persists.
- The overview diagram is tall because mermaid ignored the side-by-side layout.
  The PNG needs regenerating if the diagram changes.
